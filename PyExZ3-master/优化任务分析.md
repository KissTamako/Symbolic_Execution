## PyExZ3现状分析与PyCT风格优化方案

### 1. 当前PyExZ3实现分析

#### 主要问题（基于论文和代码分析）：

__A. 成员函数支持有限：__

- __整数类型__：仅支持`add`, `sub`, `mul`, `mod`, `floordiv`, `and`, `or`, `xor`, `lshift`, `rshift`等基础操作

- __缺失的重要函数__（根据论文Table 1）：

  - 数学函数：`abs`, `ceil`, `floor`, `round`, `trunc`
  - 比较函数：`eq`, `ne`, `lt`, `le`, `gt`, `ge`（部分已通过基类支持）
  - 类型转换：`int()`构造函数支持有限
  - 其他：`conjugate`, `denominator`, `imag`, `numerator`, `real`

- __字符串类型__：支持`len`, `contains`, `getitem`, `find`, `startswith`, `split`, `count`, `replace`, `strip`, `add`

- __缺失的字符串函数__：

  - 大小写转换：`lower`, `upper`, `isalpha`, `isdigit`, `islower`, `isupper`
  - 搜索函数：`index`, `endswith`, `find`（已支持但有限）
  - 格式化：`format`, `mod`
  - 其他：`isalnum`, `isnumeric`, `lstrip`, `rstrip`, `splitlines`

__B. 不必要的向下转换：__

- 当遇到`int(x)`, `str(x)`, `range(x,y,z)`等内置构造函数时，符号信息丢失
- 常量作为调用者时（如`"abcd".contains(x)`），常量不会提升为符号对象

### 2. PyCT优化方案设计

#### 方案B：常量提升（Constant Upcasting）技术（第二阶段）

__问题__：当常量作为调用者时（如`"abc".contains(x)`），x的符号信息会丢失。

__解决方案__：

1. __AST转换法__：在代码加载时，遍历AST，将常量提升为符号对象

   ```python
   # 原始代码
   if "abc".contains(x):
       ...

   # 转换后代码
   if SymbolicStr("const", "abc", "abc").contains(x):
       ...
   ```

2. __运行时拦截法__：通过装饰器或猴子补丁，在运行时将常量方法调用重定向到符号对象方法

__推荐实现__：AST转换法更可靠，不依赖Python内部实现。

#### 方案C：构造函数符号化（第三阶段）

__问题__：`int(x)`, `str(x)`, `range(x,y,z)`等构造函数会丢弃符号信息。

__解决方案__：

1. 重写内置构造函数的符号版本
2. 确保类型转换时保留符号表达式

def __abs__(self):
    return self._op_worker([self], lambda x: abs(x), "abs", SymbolicInteger.wrap)

def __round__(self, ndigits=None):
    if ndigits is None:
        return self._op_worker([self], lambda x: round(x), "round", SymbolicInteger.wrap)
    else:
        return self._op_worker([self, ndigits], lambda x, n: round(x, n), "round", SymbolicInteger.wrap)
